Sage Balance: Presence of Mind stack prediction¶

Live-script excerpt - from sage_balance.lua, used by the project's live-tested Sage script. The six functions below are copied unchanged and checked against the deployed module.

Presence of Mind (PoM) is tracked by the Balance route, using Telekinetic Throw. This example is not the Telekinetics route's separate Tidal Force prediction.

The useful pattern is to predict when an observation should arrive without pretending it has already arrived. The route learns Throw tick timing, counts actual damage events against its starting stack observation, and keeps that expectation separate from the buff stacks that authorize normal spender selection.

View or save the excerpt

Integration fragment, not a standalone rotation

These functions come from different scopes in the same module. The four indented helpers belong inside M.new(executor) and share its local state; the final two functions are module-level helpers. Preserve those scopes and the integration requirements below. This is not an entry point or a replacement for the full route.

Three different kinds of evidence¶

Evidence What the live code does What it does not prove
Predicted next tick time Learns activation-to-first-tick and tick-to-tick timing; publishes presence_throw_predicted_next_tick_ms That damage occurred, or that a stack was granted
Observed Throw damage ticks Adds actual matching events to the starting stack count; marks presence_stack_tick_ready when the total reaches four That the effect snapshot already contains four usable charges
Observed PoM buff stacks presence_projection(state) returns ready only when the validated observed stack count is at least PRESENCE_MAX_STACKS That a subsequent command was accepted or activated

Time passing never increments the tick count. The helper increments it only for a matching damage event while the tracked Throw is active. Despite its name, the current presence_projection function returns observed stacks and the source label "observed"; it does not promote predicted stacks into readiness.

Follow one Throw¶

An activation event starts a new channel lifecycle. The observer matches the local player's source handle and the current Throw activation handle. Damage ticks match that player, the resolved Throw name, an active lifecycle and a numeric timestamp. It does not count every damage event on the target.

The channel starts from presence_last_observed_stacks. Actual damage events advance presence_throw_tick_count; a known starting count plus those ticks reaching four creates an event-backed expectation. The full route reconciles the starting count with subsequent buff observations, rather than assuming every channel began at zero.

The timing estimator keeps running means, not an event history. After two ticks in the current channel, its interval estimate is (last_tick - first_tick) / (tick_count - 1). Before then, the code can use its explicitly retained historical interval mean. Without timing evidence, the next-tick estimate remains nil.

Reconcile before spending¶

The surrounding tick function performs the reconciliation described here; it is not included in the six-function download. Keep this step when integrating the observer. It runs after the route has read a valid state, before normal action selection.

If event counting expects four stacks but the buff still shows fewer, normal selection waits with presence_stack_tick_wait_effect. To tell a delayed snapshot from contrary evidence, the route computes the effect sample time as state.now * 1000.0 - math.max(0.0, ageMs). A sample at least 2 ms newer than the threshold damage event, still showing fewer than four stacks, clears the candidate and marks it disproved for that lifecycle. The 2 ms margin comes from the source's integer-timestamp rounding guard; it is not a general network-latency timeout.

A missing sample age cannot establish that ordering. It must not be replaced with zero. Likewise, observed_presence_stacks is safe here because the route has already rejected unavailable effect observations and present buffs with unknown charge counts. Do not call it directly on an unvalidated API response: its zero return is not an unknown-data policy.

The following is an illustrative trace, not a recorded fight. Assume two starting stacks, one received tick, and a predicted next tick at 1700 ms. The last two rows show different possible fresh observations.

Observation Interpretation
Clock reaches 1700 ms; no new damage event No new tick or stack is invented
Matching damage arrives at 1700 ms; buff still says three Two starting stacks plus two received ticks predicts completion; wait for the buff
The three-stack snapshot was sampled at 1699 ms It predates the damage event and cannot disprove the candidate
A three-stack snapshot was sampled at 1702 ms Fresh contrary evidence clears the event-backed candidate
A validated snapshot instead reports four stacks Normal selection can nominate an eligible spender; the executor still owns submission and confirmation

Integration requirements¶

Use PRESENCE_MAX_STACKS = 4, the source module's safe_method, emit_diagnostic and number_text, and the documented gos.abilities.info / gos.events.combat APIs. The effect adapter prepares state.effects.presenceOfMind with present, validated stacks, and optional ageMs mapped from public age_ms. state.now is in seconds; event timestamps and learned timing values are in milliseconds.

The closure state must be declared before the four indented helpers, inside the same route instance. These are the source initial values; do not turn them into shared globals:

Initial value Local state names
false presence_throw_active, presence_stack_tick_ready, presence_stack_tick_disproved, presence_stack_tick_suppressed, presence_completion_observed
0 presence_throw_tick_count, presence_first_tick_samples, presence_tick_interval_samples
nil - identities presence_combat_cursor, presence_player_handle, presence_throw_handle
nil - stack observations presence_stack_tick_ready_ms, presence_throw_start_stacks, presence_last_observed_stacks
nil - channel timing presence_throw_activation_ms, presence_throw_first_tick_ms, presence_throw_last_tick_ms, presence_throw_predicted_next_tick_ms
nil - learned timing / diagnostics presence_first_tick_mean_ms, presence_tick_interval_mean_ms, presence_event_fault

Read one combat batch before making the route's decision. Preserve its cursor. When more is true, the full route postpones decisions until a later bounded pass catches up; do not add an unbounded drain loop. Reconcile the validated effect state and publish presenceStackTickReady into the decision state before calling the normal selector. Update presence_last_observed_stacks from that validated snapshot for the next activation.

Interrupts and cancels reset the channel candidate. Invalid batches or dropped records reset lifecycle state instead of fabricating missed ticks. An observed player/Throw identity change also clears the learned timing means. Route deactivation resets its lifecycle and cursor. Ordinary channel resets retain timing means for later channels.

The surrounding executor handoff clears the event-ready flag and sets presence_stack_tick_suppressed after a spender submission is owned. Preserve that handoff and the existing reservation checks when integrating; an owned command is not proof that it activated. Keep exactly one top-level executor rather than creating another inside this observer.

Performance characteristics¶

This observer consumes one bounded combat batch per call, with at most 64 records under the public API contract. It filters by player before inspecting Throw events and retains scalar counters and running means rather than an ever-growing tick history. There is no per-enemy scan or render callback in the excerpt. Keep diagnostic logging gated by decisionLog; do not turn the timestamp estimate into per-frame logging or a polling loop.

Code from the live script¶

The first four functions are the closure-local observer and its helpers. The last two show the observed-stack readiness boundary. Their original indentation is preserved to make the different scopes visible.

    local function update_running_mean(mean, samples, value)
        if type(value) ~= "number" or value <= 0.0 then
            return mean, samples
        end
        samples = samples + 1
        if type(mean) ~= "number" then
            return value, samples
        end
        return mean + (value - mean) / samples, samples
    end

    local function reset_presence_lifecycle(reset_cursor)
        presence_throw_active = false
        presence_throw_tick_count = 0
        presence_stack_tick_ready = false
        presence_stack_tick_ready_ms = nil
        presence_stack_tick_disproved = false
        presence_throw_start_stacks = nil
        presence_throw_activation_ms = nil
        presence_throw_first_tick_ms = nil
        presence_throw_last_tick_ms = nil
        presence_throw_predicted_next_tick_ms = nil
        presence_completion_observed = false
        presence_event_fault = nil
        if reset_cursor then
            presence_stack_tick_suppressed = false
            presence_combat_cursor = nil
            presence_player_handle = nil
            presence_throw_handle = nil
            presence_last_observed_stacks = nil
        end
    end

    local function report_presence_event_fault(options, reason)
        if type(options) ~= "table" or options.decisionLog ~= true then
            presence_event_fault = nil
            return
        end
        if presence_event_fault == reason then
            return
        end
        presence_event_fault = reason
        emit_diagnostic(options, "warn",
            "route=balance phase=presence_lifecycle state=unavailable" ..
            " reason=" .. tostring(reason))
    end

    local function observe_presence_lifecycle(options, world)
        local player = world and world.player or nil
        local player_handle = safe_method(player, "handle")
        local throw_info = gos.abilities.info("Telekinetic Throw")
        local throw_handle = type(throw_info) == "table" and
            throw_info.activation_handle or nil
        local throw_name = type(throw_info) == "table" and
            type(throw_info.name) == "string" and throw_info.name or nil
        if type(player_handle) ~= "string" or
            type(throw_handle) ~= "string" or
            type(throw_name) ~= "string" then
            return false, false, nil, 0, 0
        end

        if (presence_player_handle ~= nil and
                presence_player_handle ~= player_handle) or
            (presence_throw_handle ~= nil and
                presence_throw_handle ~= throw_handle) then
            reset_presence_lifecycle(true)
            presence_first_tick_mean_ms = nil
            presence_first_tick_samples = 0
            presence_tick_interval_mean_ms = nil
            presence_tick_interval_samples = 0
        end
        presence_player_handle = player_handle
        presence_throw_handle = throw_handle

        local batch = gos.events.combat(presence_combat_cursor)
        if type(batch) ~= "table" or type(batch.cursor) ~= "number" or
            type(batch.dropped) ~= "number" or
            type(batch.more) ~= "boolean" or
            type(batch.events) ~= "table" then
            reset_presence_lifecycle(false)
            report_presence_event_fault(options, "invalid_batch")
            return false, false, nil, 0, 0
        end

        presence_combat_cursor = batch.cursor
        if batch.dropped > 0 then
            reset_presence_lifecycle(false)
            report_presence_event_fault(options,
                "dropped_" .. tostring(batch.dropped))
        else
            presence_event_fault = nil
        end

        for index = 1, #batch.events do
            local event = batch.events[index]
            if type(event) == "table" and
                event.source_handle == player_handle then
                local lifecycle_event = event.kind == "ability" and
                    event.ability_handle == throw_handle
                local damage_tick = event.kind == "damage" and
                    presence_throw_active and event.name == throw_name and
                    type(event.timestamp) == "number"
                if lifecycle_event and event.action == "ability_activate" then
                    presence_throw_active = true
                    presence_throw_tick_count = 0
                    presence_stack_tick_ready = false
                    presence_stack_tick_ready_ms = nil
                    presence_stack_tick_disproved = false
                    presence_stack_tick_suppressed = false
                    presence_throw_start_stacks = presence_last_observed_stacks
                    presence_throw_activation_ms =
                        type(event.timestamp) == "number" and event.timestamp or nil
                    presence_throw_first_tick_ms = nil
                    presence_throw_last_tick_ms = nil
                    presence_throw_predicted_next_tick_ms =
                        type(presence_throw_activation_ms) == "number" and
                        type(presence_first_tick_mean_ms) == "number" and
                        presence_throw_activation_ms + presence_first_tick_mean_ms or nil
                    presence_completion_observed = false
                elseif damage_tick then
                    local previous_tick_ms = presence_throw_last_tick_ms
                    presence_throw_tick_count = presence_throw_tick_count + 1
                    if not presence_stack_tick_ready and
                        not presence_stack_tick_disproved and
                        type(presence_throw_start_stacks) == "number" and
                        presence_throw_start_stacks + presence_throw_tick_count >=
                            PRESENCE_MAX_STACKS then
                        if presence_stack_tick_suppressed then
                            emit_diagnostic(options, "debug",
                                "route=balance phase=presence_handoff" ..
                                " state=late_stack_tick_ignored" ..
                                " reason=spender_executor_owned" ..
                                " start=" ..
                                    number_text(presence_throw_start_stacks, 0) ..
                                " ticks=" .. tostring(presence_throw_tick_count))
                        else
                            presence_stack_tick_ready = true
                            presence_stack_tick_ready_ms = event.timestamp
                            emit_diagnostic(options, "info",
                                "route=balance phase=presence_handoff" ..
                                " state=stack_tick_observed" ..
                                " start=" ..
                                    number_text(presence_throw_start_stacks, 0) ..
                                " ticks=" .. tostring(presence_throw_tick_count))
                        end
                    end
                    if presence_throw_first_tick_ms == nil then
                        presence_throw_first_tick_ms = event.timestamp
                        if type(presence_throw_activation_ms) == "number" and
                            event.timestamp > presence_throw_activation_ms then
                            presence_first_tick_mean_ms,
                                presence_first_tick_samples = update_running_mean(
                                    presence_first_tick_mean_ms,
                                    presence_first_tick_samples,
                                    event.timestamp - presence_throw_activation_ms)
                        end
                    end
                    if type(previous_tick_ms) == "number" and
                        event.timestamp > previous_tick_ms then
                        presence_tick_interval_mean_ms,
                            presence_tick_interval_samples = update_running_mean(
                                presence_tick_interval_mean_ms,
                                presence_tick_interval_samples,
                                event.timestamp - previous_tick_ms)
                    end
                    presence_throw_last_tick_ms = event.timestamp

                    local next_interval_ms = nil
                    if presence_throw_tick_count >= 2 and
                        type(presence_throw_first_tick_ms) == "number" and
                        event.timestamp > presence_throw_first_tick_ms then
                        next_interval_ms =
                            (event.timestamp - presence_throw_first_tick_ms) /
                            (presence_throw_tick_count - 1)
                    elseif type(presence_tick_interval_mean_ms) == "number" then
                        next_interval_ms = presence_tick_interval_mean_ms
                    end
                    presence_throw_predicted_next_tick_ms =
                        type(next_interval_ms) == "number" and
                        event.timestamp + next_interval_ms or nil
                elseif lifecycle_event and
                    (event.action == "ability_interrupt" or
                        event.action == "ability_cancel") then
                    reset_presence_lifecycle(false)
                elseif lifecycle_event and
                    event.action == "ability_deactivate" then
                    if presence_throw_active then
                        presence_completion_observed = true
                    end
                    presence_throw_active = false
                end
            end
        end

        return batch.more == true, batch.cursor, #batch.events, batch.dropped
    end

local function observed_presence_stacks(state)
    local presence = state.effects.presenceOfMind
    return presence.present and
        type(presence.stacks) == "number" and presence.stacks or 0
end

local function presence_projection(state)
    local observed = observed_presence_stacks(state)
    if observed >= PRESENCE_MAX_STACKS then
        return true, observed, "observed"
    end
    return false, observed, "observed"
end
