gos.overlay.draw_image¶

API version: 1.0.0

Draw an image at a shared screen, world or unit PointSpec.

Signature¶

gos.overlay.draw_image(id, unit_or_options, options)

Contract and usage¶

Overlay submissions are temporary. Refresh them from gos.on_tick before their TTL expires. Every draw function returns boolean success.

Every draw_* primitive accepts one shared PointSpec. One-point primitives use options.at; lines use options.from and options.to:

-- Exactly one base per point.
{ screen = { x = 100, y = 200 }, pixel_offset = { x = 0, y = 0 } }
{ world = { x = 1, y = 2, z = 3 }, pixel_offset = { x = 0, y = -10 } }
{
  unit = unit, -- or unit_handle = "unit:..."
  anchor = "origin", -- default for PointSpec units
  world_offset = { x = 0, y = 0.2, z = 0 },
  local_offset = { right = 0, up = 0, forward = 0 },
  pixel_offset = { x = 0, y = -24 },
}
{ unit = unit, anchor = "top" | "center" | "bottom",
  pixel_offset = { x = 0, y = -4 } }

World and local offsets use the same game-world units as unit:position(); 0.1 world unit is one metre. local_offset uses unit:basis() and therefore requires current rotation. Box anchors accept only pixel_offset. Screen and absolute-world points accept only pixel_offset. Malformed or conflicting point definitions raise a Lua error; temporarily unavailable position, basis, camera, or projection returns false. A queued command can still be omitted later if its point becomes unavailable or moves behind the camera.

The older unit/options and flat screen-anchor forms remain accepted for existing scripts, but new scripts should use PointSpec consistently.

Common Draw Options¶

{
  ttl = 0.25,
  frame = false,
  at = PointSpec, -- or from/to for a line
  color = color,
  thickness = number,
  center_x = boolean,
  center_y = boolean
}

Color values may be a name, packed RGBA integer, or { r = 255, g = 255, b = 255, a = 255 }. Names are white, black, gray/grey, yellow, green, red, cyan, blue, orange, and magenta.

Set frame=true for continuously redrawn UI. Core stores that command in the current callback's retained overlay frame instead of the TTL registry; the contribution is atomically replaced the next time that callback runs and remains visible across scheduler skips. Leave frame=false for intentionally persistent TTL commands. Supported alternative keys are w/h for width/height, background_color for bg_color, and num_points for segments.

PointSpec unit origins are resolved from the current authoritative render pose, not screen-box bounds, nameplate scaling, or another overlay. World/local offsets are applied in 3D, the result is projected with the current camera, and pixel_offset is applied last. No screen-box fallback is substituted.

Draw Commands¶

gos.overlay.draw_text("status", {
  at = { unit = unit, anchor = "top",
         pixel_offset = { x = 0, y = -24 } },
  text = "READY", color = "green", font_size = 16,
  shadow = true, center_x = true, ttl = 0.25,
})

gos.overlay.draw_line("line", {
  from = { screen = { x = 100, y = 100 } },
  to = { screen = { x = 220, y = 120 } },
  color = "cyan", thickness = 2,
})

gos.overlay.draw_line("cast_target", {
  from = { unit = source, anchor = "center" },
  to = { unit = target, anchor = "center" },
  color = "red", thickness = 2.5, frame = true,
})

gos.overlay.draw_line("mixed_spaces", {
  from = { screen = { x = 100, y = 100 } },
  to = { unit = target, anchor = "origin",
         world_offset = { x = 0, y = 0.2, z = 0 } },
  color = "cyan", thickness = 2,
})

gos.overlay.draw_rect("rect", {
  at = { unit = unit, anchor = "top",
         pixel_offset = { x = -40, y = -14 } },
  width = 80, height = 10,
  color = "yellow", filled = false, rounding = 2,
})

gos.overlay.draw_bar("health", {
  at = { unit = unit, anchor = "top",
         pixel_offset = { x = -45, y = -18 } },
  width = 90, height = 6,
  value = 0.5, color = "green",
  bg_color = { r = 12, g = 14, b = 16, a = 220 },
  border = true, border_color = "black",
})

gos.overlay.draw_circle("screen_circle", {
  at = { unit = unit, anchor = "center" },
  radius = 18, color = "orange",
  segments = 32, filled = false,
})

gos.overlay.draw_image("icon", {
  at = { unit = unit, anchor = "origin",
         world_offset = { x = 0, y = 0.2, z = 0 },
         pixel_offset = { x = 0, y = -24 } },
  path = SPRITE_PATH .. "icon.png", width = 24, height = 24,
  tint = "white", center_x = true,
})

gos.overlay.draw_rectangle is an alias for gos.overlay.draw_rect. Text supports font_size and shadow. Rectangles support filled, fill_color, rounding, and optional border fields. Bars clamp value to 0..1. Images use their texture size when width or height is omitted.

Image paths must remain inside the active script application's approved filesystem roots. Relative paths use SCRIPT_PATH; SPRITE_PATH is suitable for packaged images. Network-share, device and URL paths, or resolved paths escaping the approved roots, are rejected by image loading. Path validation and decoding run on an image worker; a successful drawing submission does not prove that an image was decoded or displayed.

PointSpec circles use radius for screen pixels or the mutually exclusive world_radius for an unfilled X/Z world circle. world_radius requires an absolute world point or current unit origin. A position-backed circle is independent of later unit visibility, so a persistent TTL marker remains at the supplied coordinates after that unit leaves the current snapshot. One coordinate unit currently represents 10 metres, so a 30-metre circle uses world_radius = 3:

gos.overlay.draw_circle("range", {
  at = { unit = unit, anchor = "origin" },
  world_radius = 30 / 10,
  color = "cyan",
  segments = 64,
  thickness = 2,
})

-- Persistent last-known world position; no unit is required after submission.
gos.overlay.draw_circle("last_seen", {
  at = { world = { x = last.x, y = last.y, z = last.z } },
  world_radius = 8 / 10,
  color = "magenta",
  thickness = 3,
  ttl = 8,
})

The Release snapshot retains at most 512 active draw commands across frame-local and persistent output. A single callback may contribute at most 192 frame-local commands. IDs contain at most 31 bytes, text at most 63 bytes, and image paths at most 259 bytes. Oversized drawing IDs, text and image paths are truncated, not rejected; keep them within those byte limits to avoid collisions or unusable paths. Replacement matches callback owner, target identity, draw kind and the resulting ID. Reusing only the ID with another target or draw kind can leave a separate TTL drawing alive. Frame-local output supports at most 32 callback owners; these limits are shared with other scripts.
