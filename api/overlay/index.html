Drawing and interaction¶

Overlay submissions are temporary. Refresh them from gos.on_tick before their TTL expires. Every draw function returns boolean success.

Unit-anchored commands accept either form:

gos.overlay.draw_text("id", unit, { ... })
gos.overlay.draw_text("id", { unit = unit, ... })
gos.overlay.draw_text("id", { unit_handle = "unit:...", ... })

Screen-space commands omit a unit and use anchor = "screen".

Common Draw Options¶

{
  ttl = 0.25,
  frame = false,
  anchor = "screen" | "top" | "center" | "middle" | "bottom",
  x = number,
  y = number,
  color = color,
  thickness = number,
  center_x = boolean,
  center_y = boolean
}

Color values may be a name, packed RGBA integer, or { r = 255, g = 255, b = 255, a = 255 }. Names are white, black, gray/grey, yellow, green, red, cyan, blue, orange, and magenta.

Set frame=true for continuously redrawn UI. Core stores that command in the current callback's retained overlay frame instead of the TTL registry; the contribution is atomically replaced the next time that callback runs and remains visible across scheduler skips. Leave frame=false for intentionally persistent TTL commands. Unit commands default to bottom; screen commands default to screen. Supported alternative keys are w/h for width/height, background_color for bg_color, and num_points for segments. For lines, to_unit (or release-safe to_unit_handle) creates a unit-to-unit line. Both endpoints must resolve to current, on-screen Core units; otherwise the draw request fails closed. screen anchors are not valid for unit-to-unit lines.

Draw Commands¶

gos.overlay.draw_text("status", unit, {
  anchor = "top", x = 0, y = -24,
  text = "READY", color = "green", font_size = 16,
  shadow = true, center_x = true, ttl = 0.25,
})

gos.overlay.draw_line("line", {
  anchor = "screen", x1 = 100, y1 = 100, x2 = 220, y2 = 120,
  color = "cyan", thickness = 2,
})

-- Exact current unit-to-unit relationship. The same anchor is used at both
-- endpoints; x1/y1 offset the source and x2/y2 offset the destination.
gos.overlay.draw_line("cast_target", source, {
  to_unit = target, anchor = "center",
  color = "red", thickness = 2.5, frame = true,
})

gos.overlay.draw_rect("rect", unit, {
  anchor = "top", x = -40, y = -14, width = 80, height = 10,
  color = "yellow", filled = false, rounding = 2,
})

gos.overlay.draw_bar("health", unit, {
  anchor = "top", x = -45, y = -18, width = 90, height = 6,
  value = 0.5, color = "green",
  bg_color = { r = 12, g = 14, b = 16, a = 220 },
  border = true, border_color = "black",
})

gos.overlay.draw_circle("screen_circle", unit, {
  anchor = "center", radius = 18, color = "orange",
  segments = 32, filled = false,
})

gos.overlay.draw_image("icon", unit, {
  anchor = "top", path = SPRITE_PATH .. "icon.png",
  x = 0, y = -42, width = 24, height = 24,
  tint = "white", center_x = true,
})

gos.overlay.draw_rectangle is an alias for gos.overlay.draw_rect. Text supports font_size and shadow. Rectangles support filled, fill_color, rounding, and optional border fields. Bars clamp value to 0..1. Images use their texture size when width or height is omitted.

World-space circles must be unfilled and use game-world coordinate units. They may be anchored either to a current unit or to an explicit captured world position. A position-backed circle is independent of later unit visibility, so a persistent TTL marker remains at the supplied coordinates after that unit leaves the current snapshot. One coordinate unit currently represents 10 metres, so a 30-metre circle uses radius = 3:

gos.overlay.draw_circle("range", unit, {
  world_space = true,
  radius = 30 / 10,
  color = "cyan",
  segments = 64,
  thickness = 2,
})

-- Persistent last-known world position; no unit is required after submission.
gos.overlay.draw_circle("last_seen", {
  world_space = true,
  position = { x = last.x, y = last.y, z = last.z },
  radius = 8 / 10,
  color = "magenta",
  thickness = 3,
  ttl = 8,
})

The Release snapshot retains at most 512 active draw commands across frame-local and persistent output. A single callback may contribute at most 192 frame-local commands. IDs contain at most 31 bytes, text at most 63 bytes, and image paths at most 259 bytes. Oversized drawing IDs, text and image paths are truncated, not rejected; keep them within those byte limits to avoid collisions or unusable paths. Replacement matches callback owner, target identity, draw kind and the resulting ID. Reusing only the ID with another target or draw kind can leave a separate TTL drawing alive. Frame-local output supports at most 32 callback owners; these limits are shared with other scripts.

gos.overlay.unit_label(id, unit, options)¶

This legacy label helper accepts text, a named color, and ttl. It does not implement the generic draw_* options such as frame, anchor, font sizing or RGBA color tables; use draw_text for those features.

Adds or refreshes a simple unit label:

local ok = gos.overlay.unit_label("focus", unit, {
  text = "FOCUS",
  color = "red",
  ttl = 0.25,
})

The Release snapshot retains at most 32 active labels.

gos.overlay.viewport()¶

Returns the exact current render viewport:

{
  available = boolean,
  width = integer | nil,
  height = integer | nil
}

No guessed dimensions are returned when available=false.

gos.overlay.interact(id, rect)¶

Requires an active script callback. An empty or over-31-byte ID, invalid rectangle, nonpositive TTL, or wrong arguments raise a Lua error. Unlike ordinary draw IDs, interaction IDs are validated rather than truncated. Registers a temporary screen rectangle and returns left-mouse interaction:

local state = gos.overlay.interact("button", {
  x = 20, y = 20, width = 120, height = 28, ttl = 0.25,
})

-- state:
{
  hovered = boolean,
  pressed = boolean,
  down = boolean,
  released = boolean,
  clicked = boolean,
  mouse_x = number,
  mouse_y = number
}

Refresh the rectangle before its TTL expires. A press retains capture through release. The Release snapshot retains at most 64 active interaction rectangles, with at most 40 contributed by one callback owner, subject to the 32-owner frame ceiling. If registration or input observation is unavailable, the result can contain all false flags and zero coordinates with no separate availability flag. That state alone is not proof that the pointer is outside the rectangle; stay within the published budgets.
